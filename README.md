# Workspace — корпоративная база знаний и командная работа

Самостоятельно хостящаяся платформа уровня Notion: файловое хранилище
документов (без БД для контента), жёсткое разграничение ролей, блочный
редактор, чат с видеозвонками в реальном времени, presence, комментарии
и полноценная кастомизация под свой бренд.

Другие документы:

- **[install.md](./install.md)** — пошаговая установка с нуля: зависимости,
  `.env`, первый администратор, сборка, PM2, nginx, свой STUN/TURN
  (coturn) для видеозвонков, финальный чек-лист проверки.
- **[agent.md](./agent.md)** — правила для нейросети/ассистента, работающей
  с этим репозиторием.
- **[changelog.md](./changelog.md)** — история изменений.
- READMEs внутри `packages/*` — API каждого модуля.

## Что это

Единое SPA-приложение с сайдбаром, где:

- у каждого пользователя есть личное корневое пространство: проекты,
  вложенные страницы (статьи) и **отдельное личное файловое хранилище**
  (`/files`) — всё внутри одной папки `users/{userId}/` на диске;
- страницы редактируются блочным редактором: `/`-команды, заголовки,
  списки, чек-листы, код, callout, таблицы, разделитель — плюс **инлайн-
  форматирование текста** (жирный/курсив/зачёркнутый/код/ссылка,
  кликабельные ссылки с Ctrl/Cmd+клик) и вставка **изображений и файлов**
  — командой `/Изображение` / `/Файл` (тулбар дублирует те же действия),
  перетаскиванием с компьютера или вставкой из буфера обмена (Ctrl/Cmd+V)
  — все четыре способа ведут в одно личное файловое хранилище. Вставка
  текста из буфера сохраняет структуру (заголовки/списки/цитаты) и
  форматирование исходника; блоки можно перетаскивать вверх/вниз мышью за
  ручку слева и удалять по одному (кнопка-корзина у каждого блока,
  включая картинки/файлы/разделитель);
- у редактора — сворачиваемый **сайдбар** (ярлык страницы, оглавление по
  заголовкам, связанные документы — ссылки, вставленные прямо в текст
  через тулбар блока, свои и расшаренные с вами — и теги). Все секции
  пересчитываются напрямую из содержимого документа, не хранятся
  отдельно. Там же — действия с документом: дочерняя страница,
  скачивание в .md/.txt/.pdf, печать (в печать/PDF попадает только сам
  документ, без интерфейса вокруг);
- под статьёй — **комментарии**: плоский список (без вложенных тредов),
  Markdown, реакции-эмодзи, редактирование/удаление своих — доступ по
  тому же уровню `Comment` из прав на страницу, что и в диалоге
  «Поделиться» ниже;
- на главной странице — **единое дерево документов**: своё дерево страниц
  плюс секция «Расшаренные со мной» под ним в том же сайдбаре, и то, и
  другое открывается в одном и том же редакторе (чужая страница — в
  режиме чтения или редактирования, в зависимости от выданного уровня
  доступа);
- страницы можно расшарить с уровнем доступа `Read / Comment / Edit /
  Admin` через диалог «Поделиться» прямо в редакторе, либо выдать доступ
  всем по ссылке;
- есть отдельная страница **«Расшаренные со мной»** (`/shared`) — тот же
  список отдельным полноэкранным видом, для случаев, когда сайдбар тесен;
- у администратора есть **админ-панель** (`/admin`): создание,
  редактирование (имя/роль), удаление пользователей, сброс пароля,
  приглашения по ссылке;
- есть **чат** (`/chat`) — личные и групповые беседы, живая доставка
  сообщений и индикатор «печатает...» через сокеты, треды (разворачиваются
  по клику на сообщении), Markdown-форматирование (в том числе
  распознаётся при вставке скопированного форматированного текста),
  реакции-эмодзи, редактирование/удаление своих сообщений, вложения —
  и ссылки на свои страницы (карточка с проверкой доступа получателя),
  и файлы/картинки/видео с компьютера (разрешённые типы — через
  `CHAT_ALLOWED_MIME_TYPES` в `.env`);
- есть **видеозвонки** прямо в чате (личные и групповые, до 8 участников,
  mesh-топология) — свой STUN/TURN (coturn), без сторонних сервисов;
  демонстрация экрана; оповещение о входящем звонке видно на любой
  странице, не только в открытом чате;
- у каждого пользователя — **настройки профиля** (`/settings`): свой
  аватар кружком (из личного файлового хранилища, автоматически
  обрезается под квадрат и уменьшается) и акцентный цвет интерфейса
  (8 приглушённых пресетов, красят кнопки/ссылки/свои сообщения в чате
  сразу же, без перезагрузки);
- у администратора — **настройки сайта** (`/admin`): название,
  описание, копирайт, логотип — применяются везде, включая экран входа
  (единственный по-настоящему публичный, без токена, эндпоинт во всём
  проекте — иначе экрану логина нечем было бы это показать);
- видно, кто сейчас онлайн на странице (presence), с аватарами.

Создать аккаунт самостоятельно нельзя — только администратор создаёт
пользователей или отправляет приглашение. Подробности — в
[install.md](./install.md#4-создание-первого-администратора-и-остальных-пользователей).

## Архитектура

Монорепозиторий (npm workspaces + Turborepo):

```
packages/
  core-fs-engine/   Файловое хранилище документов и файлов — единственный
                     модуль, который трогает диск (users/projects/pages/
                     history/assets/files/credentials/site-settings)
  core-auth/        JWT + RBAC (Admin/Team-Lead/Member/Guest), никакой
                     самостоятельной регистрации
  core-realtime/    Socket.io: presence, курсоры, live-патчи, живая
                     доставка сообщений чата
  core-chat/        Личные/групповые чаты, треды, реакции, вложения,
                     JSONL-хранилище
  core-webrtc/      Сигналинг для видеозвонков (до 8 участников) + свой
                     STUN/TURN (coturn) вместо сторонних сервисов

apps/
  server/           Express API + Socket.io сервер, связывающий пакеты
                     (роуты: auth, admin, storage, chats, users, shared,
                     files, webrtc, site-settings)
  web/               Next.js SPA — сайдбар с общим деревом (свои +
                     расшаренные), редактор, чат, видеозвонки, настройки
                     профиля и сайта, тема, presence
```

Ни один модуль, кроме `@core/fs-engine`, не обращается к файловой системе
напрямую — это единственная точка входа к диску, и именно там реализована
защита от path traversal, атомарная запись и блокировки на конкурентную
запись. Личное файловое хранилище пользователя (`users/{userId}/files/`)
живёт в той же папке, что и его статьи (`users/{userId}/{projectId}/pages/`)
— ровно так, как и просили: одна папка на пользователя ровно с двумя
видами содержимого, статьи и файлы. Аватар — обычный файл в этой же
папке, не отдельная сущность; общесайтовые настройки (название, логотип)
— наоборот, намеренно не в папке никакого пользователя, а прямо в корне
хранилища, потому что не принадлежат никому конкретному.

## Технологии

React 18 + Next.js (App Router), Zustand, Tailwind CSS, Express, Socket.io,
JWT (`jsonwebtoken` + `bcryptjs`), Turborepo, TypeScript strict-mode
повсюду.

## Известные ограничения

- Блочный редактор — собственная реализация на `contentEditable`, а не
  Slate.js/Lexical. Классический баг «курсор прыгает при вводе» смягчён
  (см. `EditableBlockContent` в `apps/web/components/Editor.tsx` —
  синхронизация DOM ↔ state сделана императивно через `ref`+`useEffect`,
  а не реактивным `dangerouslySetInnerHTML`), но это обход, а не полное
  решение уровня настоящего rich-text движка. Схема `PageBlock[]` уже
  готова для переезда на Lexical, если понадобится больше, чем базовое
  инлайн-форматирование.
- Инлайн-форматирование (жирный/курсив/зачёркнутый/код/ссылка) хранится
  как HTML внутри `PageBlock.content` и санитизируется client-side
  (`apps/web/lib/sanitize.ts`, allowlist на `b/strong/i/em/s/u/code/a/br`)
  перед сохранением — это защита от stored XSS в расшаренных статьях, но
  **не замена серверной валидации**: клиент, обращающийся к API напрямую
  (не через веб-интерфейс), теоретически может записать произвольный HTML
  в `content.json`. Для продакшена стоит добавить такую же санитизацию на
  сервере в `FsEngine.savePageContent`.
- `<img>`/`<a>` не могут отправить `Authorization`-заголовок, поэтому для
  них токен доступа передаётся через `?token=` в URL (см.
  `apps/web/lib/api.ts:withAuthToken`, `@core/auth` `requireAuth`). Токен
  короткоживущий (15 минут), но всё равно виден в URL — при копировании
  ссылки на файл (кнопка в `/files`) это стоит иметь в виду.
- Учётные данные (`STORAGE_ROOT/auth/credentials.json`, управляется через
  `FsEngine`) хранятся в одном JSON-файле, а не в отдельной БД с индексами
  и миграциями — переживает перезапуски и подходит для команд среднего
  размера, но не рассчитан на тысячи пользователей или сложные запросы.
  Файл содержит bcrypt-хеши, не сами пароли, но всё равно ограничь права
  на `STORAGE_ROOT` (см. `install.md`, раздел «Создание первого
  администратора» → «Важно»).
- Поиск (`FsEngine.searchPages`) — линейный перебор файлов, а не индекс
  Fuse.js/Lunr.
- **История версий страниц — backend без интерфейса.**
  `FsEngine.listHistory`/`restoreHistorySnapshot` и соответствующие роуты
  в `storage.routes.ts` работают (снапшот пишется при каждом сохранении
  контента), но открыть список версий или восстановить старую через
  интерфейс сейчас негде — ни кнопки, ни страницы для этого нет.
- Автотесты в этой версии отсутствуют. Есть глобальный `tsc` в среде
  разработки, использовался для проверки синтаксиса каждого файла
  (`tsc --noEmit` без `node_modules` — ловит реальные ошибки парсинга, но
  не полную типизацию, поскольку типы пакетов не резолвятся без
  установленных зависимостей) — полноценная проверка типов всё равно не
  проводилась. При первом реальном запуске стоит прогнать `npm install`
  и `npm run typecheck` по всем пакетам.
